# 개인정보·보안 가이드

## 개인정보·보안·학교 환경 확인

교육용 프로그램일 가능성이 있으므로 관련이 있을 때 다음 사항을 반드시 확인한다.

- 학생 이름
- 학번
- 연락처
- 성적
- 출결
- 상담 기록
- 사진과 영상
- 건강 정보
- 학부모 정보
- 미성년자 개인정보
- 외부 AI 서비스로 전송되는 정보
- 학교 또는 교육청의 보안 정책
- 자료 보관 기간
- 자료 삭제 방법
- 사용자별 접근 권한
- 관리자 접근 범위
- 백업과 복구
- 학교 내부망 사용 여부
- 공개 인터넷 서비스 여부

다음 원칙을 적용한다.

- 필요한 개인정보만 최소한으로 수집한다.
- 수집 목적이 분명하지 않은 정보는 저장하지 않도록 제안한다.
- 역할별로 필요한 정보만 열람하게 한다.
- 학생 개인정보를 개발용 예시나 로그에 그대로 넣지 않도록 한다.
- 실제 학생 정보 대신 가상 데이터로 시제품을 만들 수 있는지 확인한다.
- 비밀번호, API 키, 비밀값을 소스코드에 직접 작성하지 않도록 명세한다.
- 중요한 작업에는 입력 검증과 권한 확인을 요구한다.
- 개인정보가 로그, 오류 메시지 또는 URL에 노출되지 않도록 고려한다.
- 외부 AI 서비스로 전송되는 데이터와 그 필요성을 명확히 한다.
- 자료 삭제와 계정 삭제 시 처리 방식을 정한다.
- 백업 자료의 보관 및 삭제도 고려한다.

법률, 규정 또는 기관 정책을 확정적으로 단정하지 않는다.

확인이 필요한 법적·정책적 사항은 다음과 같이 표시한다.

- 확인이 필요한 사항
- 확인해야 할 담당자 또는 기관
- 확인 전에는 사용하지 말아야 할 기능
- 개인정보를 제외하고 시제품을 만드는 대안

이 스킬은 설계 단계의 개인정보·보안 검토를 지원하지만 다음을 대체하지 않는다고 명확히 한다.

- 법률 전문가 검토
- 학교 또는 교육청의 공식 보안 승인
- 실제 소스코드 보안 감사
- 클라우드 보안 설정 점검
- 모의해킹 또는 침투 테스트

보안 요구사항은 다음 세 단계로 구분한다.

1. 개발 전에 확인할 사항
2. 개발 중 구현할 사항
3. 배포 전에 검증할 사항

## 발견과 기록

“학생 이름이나 점수·사진처럼 보호해야 할 정보가 들어가나요?”처럼 묻고 실제 학생 기록을 답변에 붙여넣도록 요구하지 않는다. 미성년자 정보라면 열람·수정 주체, 외부 전송, 기관 정책을 확인한다.

검토표는 정보 항목 / 목적·필요성 / 최소화·가명화 대안 / 접근 역할·학교 경계 / 저장 위치 / 외부·AI 전송 / 보관·삭제·백업 / 담당자 / 확인 상태로 작성한다. 이름 제거만으로 익명화되었다고 단정하지 않는다.

## 단계별 확인

- 개발 전: 최소 수집, 기관 정책·외부 제공 조건·담당자를 확인한다. 확인 전 사용하지 않을 기능과 가상 데이터 대안을 기록한다.
- 개발 중: 서버 측 최소 권한·입력 검증·인증·세션·전송 보호를 구현한다. 코드·브라우저·URL에 비밀값을 두지 않고 로그·오류의 개인정보를 제거한다.
- 배포 전: 타 사용자·타 학급 접근 차단, 세션 만료·로그아웃, 자료·계정 삭제, 비공개 파일, 운영 설정, 비밀값 노출, 백업 복원·만료 삭제를 검증한다.

외부 AI는 전송 항목·식별정보 제거·수신 서비스·보관 조건·정확성 검토자·오류 결과 처리·생성 표시·비용 제한을 정한다. 중요한 평가 결과는 검토 없이 확정하지 않도록 요구사항에 적는다.

보관 기간은 근거 없이 확정하지 않는다. 삭제 대상은 원본·첨부·내보내기·백업까지 고려하고 복원 시 삭제 자료가 되살아나는 문제도 다룬다.

## 가상 데이터 시제품

실제 기록 복사 대신 가상의 학생·학급·점수·사진 대체물을 사용하고 데모임을 표시한다. 실데이터 전환 전에 권한·기관 정책·저장 위치를 확인한다. 이 검토는 위험 발견과 요구사항 작성 수준이며 전문 법률·보안 검토나 기관 승인을 보증하지 않는다.
