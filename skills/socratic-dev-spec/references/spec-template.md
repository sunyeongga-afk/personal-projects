# 개발명세서 템플릿

아래 구조를 구체적으로 채운다. 해당하지 않는 항목은 해당 없음과 이유를 적는다. 미확인 값은 가정 또는 미결정으로 표시하고 빈 양식을 결과로 내보내지 않는다. FR을 화면·API·테스트·인수 조건·구현 단계와 연결한다.

## 28. 선택 사항: 새로운 DESIGN.md 초안

다음 경우 새로운 DESIGN.md 초안을 제공한다.

- 사용자가 DESIGN.md 작성을 요청한 경우
- 기존 DESIGN.md가 없고 디자인 방향이 충분히 합의된 경우
- 기존 DESIGN.md를 현재 프로젝트에 맞게 정리해달라고 요청한 경우

DESIGN.md 초안에는 다음을 포함한다.

- 디자인 목표
- 주요 사용자
- 디자인 원칙
- 색상
- 타이포그래피
- 간격과 레이아웃
- 공통 컴포넌트
- 화면 상태
- 반응형 기준
- 접근성
- 금지 사항
- 구현 시 확인 목록

## 작성 형식 보완

- NFR: ID / 요구 / 적용 범위 / 측정 기준·목표 / 검증 방법 / 근거 또는 가정. 수치는 합의하거나 가정으로 표시한다.
- 화면: ID / 목적·역할 / 진입·이탈 / 표시 정보 / 입력·행동 / 관련 FR / 로딩·빈·오류·성공 상태 / 반응형·접근성.
- 디자인 분석: 출처 / 필수·권장·미결정 / 충돌·결정 / 그대로 반영 / 조정과 이유 / 확인 방법.
- 디자인 원칙: 원칙 / 근거 / 적용 화면 / 색상·글자·간격 등 구체 규칙 / 검증 방법.
- 개인정보·보안: 정보·목적 / 접근 주체 / 저장·전송 / 보관·삭제·백업 / 개발 전 확인 / 개발 중 구현 / 배포 전 검증 / 담당자·미결정.
- 데이터: 엔터티·필드 / 자료형 / 필수 / 고유 / 키·관계 / 삭제 처리 / 민감정보 / 가상 예시.
- 인수 조건: AC-ID / 관련 FR·NFR / Given / When / Then. 해당 기능의 권한 거부·입력 오류·실패 복구도 포함한다.
- 구현 단계: 목표 / 관련 FR / 구현 내용 / 완료 조건 / 검증 / 다음 단계 전 확인.
- 구현 프롬프트는 명세와 디자인 자료를 참조하고 확정·가정·미결정을 구분한다. 1단계 핵심 흐름부터 구현→검증→다음 단계로 진행하게 한다. 서비스 생성·실제 배포를 명세 작성만으로 승인하지 않는다.
