# AI 코딩 도구에 전달할 구현 요청

SPEC.md와 DESIGN.md를 읽고 ‘취업 면접 연습실’ 웹앱 시제품을 구현해 주세요. 확정·가정·후속 미결정을 구별하고 완료되지 않은 기능을 완료했다고 보고하지 마세요.

대상은 특성화고·마이스터고 학생(휴대폰)과 담당 교사(PC)입니다. 밝은 배경과 파란색의 단정한 반응형 화면을 만듭니다. 간단 지원 정보 또는 자기소개서 입력 → 준비된 예상 질문·꼬리 질문·답변 요령 → 답변 작성 → 고정 피드백 예시 → 수정 이력 → 교사 의견 → 인쇄까지 연결합니다.

React·TypeScript·Vite와 CSS를 기본 제안으로 사용하되 기존 프로젝트가 있다면 먼저 구조와 지침을 확인하세요. 외부 계정, 실제 AI API, 서버, 실제 인증은 만들지 마세요. 역할 체험과 가상 학생 3명, 가상 교사 1명, 생산·전기/설비·사무 직무별 질문 8개를 기본 가정으로 사용하세요. 미지원 직무에는 공통 예시임을 알려 주세요. 자유 입력을 실제 AI로 분석했다고 표현하지 마세요.

데이터 모델은 SPEC.md 11절을 따르고 화면과 자료 처리 계층을 분리하세요. localStorage에는 앱 전용 키와 스키마 버전을 쓰고 저장 실패·손상 자료를 처리하세요. 학생별 기록과 담당 관계를 검사하되 이를 실제 보안 인증이라고 설명하지 마세요. 교사는 학생 답변을 바꾸지 않고 의견을 남깁니다. 가상 정보만 쓰도록 안내하고 답변을 URL·로그·외부 서비스로 전송하지 마세요. API 키나 비밀번호를 넣지 마세요.

전체를 한 번에 생성하지 말고 아래 각 단계를 구현하고 검증한 다음 진행하세요.

1. 프로젝트 구조와 실행 방법, 데모 데이터, S01~S03과 두 입력 경로를 구현합니다. 필수값 검증·미지원 직무·예시 표시를 확인합니다.
2. S04~S05에 답변 저장·고정 예시 피드백·수정 이력·재접속 복원을 구현합니다. 학생 간 기록 분리와 저장 실패 시 입력 보존을 검증합니다.
3. S06~S07 교사 목록·상세·의견을 구현합니다. 담당 외 접근 거부와 학생 측 의견 확인을 검증합니다.
4. 인쇄·초기화·모바일·접근성을 완성합니다. SPEC.md의 AC-01~11을 확인하고 결과·남은 제한을 기록합니다. 의미 있는 저장·분리·복구 검증을 작성하고 단순 화면 구현을 그대로 반복하는 테스트는 피하세요.

키보드 사용·포커스·200% 확대·360px 화면·교사 PC·인쇄에서 읽을 수 있어야 합니다. 피드백마다 ‘작성한 답변을 분석한 결과가 아닌 준비된 피드백 예시’를 표시하세요. 질문 자료와 인쇄에도 체험 표시를 유지하세요.
