# 교사 도구함 — 단계별 바이브코딩 프롬프트

## 공통 지시: 먼저 함께 전달

전문교과 교사가 개인적으로 사용할 프로그램 허브를 구현하세요. 같은 폴더의 개발명세서.md가 기능·데이터·인수 기준이고, 사용자가 제공한 DESIGN (1).md는 디자인 출처입니다. 원본 디자인 문서 속 구매·쿠키 배너 등 예시를 필수 기능으로 추가하지 마세요. 개발명세서 9절의 한글 가독성·접근성 조정을 함께 적용하세요.

확정: PC 중심 반응형 웹앱, 외부 웹주소 등록·수정·삭제, 코드로 내부 앱 추가, 첫 내부 앱 계산기, localStorage 저장, JSON 백업·복원, 로그인·백엔드·DB 없음.

가정: HTML/CSS/JavaScript ES 모듈, 해시 라우팅, 프레임워크·런타임 CDN 없음, 입력 순서대로 연산하는 일반 계산기, 계산 기록 미저장, 학생 개인정보 없음, 복원은 외부 목록 전체 교체. 나머지 가정과 제한은 명세서 23절 및 관련 FR을 읽고 따르세요. 미결정인 호스팅·도메인은 생성하지 마세요.

시작 전에 작업 폴더와 적용되는 AGENTS.md를 확인하세요. 기존 프로젝트가 있으면 먼저 구조를 조사하고 무관한 파일을 덮어쓰지 마세요. 프로젝트는 독립 폴더에 구성하고 원본 디자인 파일은 보존하세요. 세부 기술 선택을 바꿔야 한다면 이유와 영향을 기록하세요.

학생 개인정보·외부 AI·분석 추적·비밀 API 키를 추가하지 마세요. URL은 http/https만 허용하고 새 탭은 noopener/noreferrer로 여세요. 사용자 문자열은 텍스트로 출력하세요. eval 없이 계산하세요. 백업 파일은 실행하지 말고 전체 스키마 검증을 통과한 데이터만 적용하세요.

각 단계에서 구현 후 관련 인수 조건을 검증하고 실제 실행 여부와 미검증 항목을 구분해 보고하세요. 완료되지 않은 검증을 통과했다고 쓰지 마세요. 전체를 한 번에 생성하지 말고 아래 단계를 순서대로 수행하세요. 실제 배포·외부 계정 생성은 별도 요청 없이는 수행하지 마세요.

## 1단계 — 허브에서 계산기 실행

명세서 FR-001·007과 S01·S04를 먼저 구현하세요. CSS 변수로 색상·여백·직각·얇은 구분선을 적용하세요. 허브, 내부 앱 레지스트리, 해시 라우터, mount/cleanup 규칙, 허브 복귀 링크를 만드세요. 계산 엔진은 화면과 분리한 순수 함수로 구성하세요.

사칙연산, 소수점, ±, AC, 한 자리 지우기, 키보드를 구현하세요. 명세서의 연산 순서·연산자 교체·결과 후 입력·반복 =·정밀도·12자리 제한·오류 복구 규칙을 따르세요. 외부 앱 관리 버튼은 작동하지 않는 가짜 버튼으로 남기지 말고 이후 구현 예정임을 텍스트로 표시하세요.

AC-001·007·008·009를 검증하세요. PC와 모바일 너비에서 숫자 표시와 버튼이 잘리지 않는지 확인하세요. 이 단계의 작동 화면과 실행 방법을 README에 기록한 뒤 다음 단계로 진행하세요.

## 2단계 — 외부 프로그램 등록과 저장

FR-002~004와 S02를 추가하세요. name/description/url을 입력하고 고유 ID를 생성하세요. 코드 내부 앱과 외부 앱의 관리 방식을 구분하세요. 내부 앱에는 화면의 수정·삭제 기능을 붙이지 마세요.

입력 검증과 저장 어댑터를 분리하고 버전 있는 데이터를 localStorage에 저장하세요. 저장 성공 전 성공 UI로 확정하지 마세요. 실패하면 입력값과 기존 목록을 유지하세요. 손상된 저장값은 자동 초기화·덮어쓰기하지 말고 원문 다운로드와 사용자가 확인하는 초기화를 제공하세요. 수정·삭제·취소·저장 후 새로고침을 확인하세요.

AC-002·003·004·011·013과 위험 URL·HTML 형태의 이름을 검증하세요. 핵심 계산기 흐름에 영향이 없는지 확인한 뒤 다음 단계로 진행하세요.

## 3단계 — 백업과 복원

FR-005·006과 S03을 구현하세요. 백업에는 schemaVersion/exportedAt/externalApps만 포함하고 내부 앱 코드나 계산값은 넣지 마세요. 파일 크기·항목 수·자료형·필수값·URL·중복 ID·버전을 전체 검증하세요. 허용된 필드만 새 객체에 복사하세요.

가져오기는 미리보기에서 외부 목록이 전체 교체된다는 점과 항목 수를 보여주고 확인 후 적용하세요. 저장이 성공해야 화면 상태를 교체하세요. 검증 오류·취소·저장 실패 시 기존 데이터는 유지하세요. 교체 전 현재 목록을 내보낼 수 있도록 안내와 동작을 제공하세요.

AC-005·006·014 및 AC-011의 복원 저장 실패를 검증하세요. 빈 목록 왕복, 잘못된 JSON, 미지원 버전, 중복 ID, 위험 URL, 용량 초과를 확인한 뒤 진행하세요.

## 4단계 — 확장 규칙과 사용성 마무리

FR-008과 NFR-001~007을 검증하세요. 새 내부 앱을 모듈·레지스트리 추가만으로 연결하는 절차를 README에 작성하세요. 코드 백업과 목록 백업의 차이, 브라우저 프로필·운영 주소 변경 시 저장 공간이 달라지는 점, 로컬 HTTP 실행법을 설명하세요.

임시 예제 모듈로 확장을 검증하고 이동 시 리스너가 해제되는지 확인하세요. 제품에 불필요한 예제 앱은 남기지 마세요. 키보드 포커스, 입력 레이블, 상태 알림, 색상 대비, 200% 확대, 360/768/1440px 화면과 PC 우선 브라우저·모바일 하나를 확인하세요.

핵심 인수 조건 결과를 통과·실패·미검증으로 기록하고 실패를 수정하세요. 마지막에는 변경 내용, 실행 방법, 검증 결과, 남은 가정·제약을 간결하게 보고하세요. 배포는 진행하지 마세요.
