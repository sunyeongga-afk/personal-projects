# 개인용 프로그램 허브 개발명세서

작성일: 2026-10-17 · 상태: 사용자 합의에 따른 구현 기준안 · 가칭: 교사 도구함

## 1. 프로젝트 기본 정보

전문교과 교사가 바이브 코딩으로 만드는 프로그램과 기존 웹앱을 한곳에서 찾아 실행하는 개인용 웹 허브다. 첫 번째 내부 앱은 기본 계산기다. 프로그램마다 주소와 파일을 따로 찾아야 하는 불편을 줄인다.

성공 기준은 허브에서 계산기를 실행하고, 외부 웹앱을 등록하고, 새로고침 후에도 목록을 유지하고, 백업으로 다른 브라우저에 목록을 복원하는 것이다.

## 2. 사용자와 권한

주요 사용자와 관리자는 선생님 본인 한 명이다. 목록 조회·등록·수정·삭제·백업을 모두 수행한다. 학생·다른 교사 계정과 역할 구분은 첫 버전에 없다. 로그인은 없으며 같은 기기·브라우저 프로필을 사용하는 사람도 저장된 목록에 접근할 수 있다.

## 3. 실행 환경

PC 브라우저 중심의 반응형 웹앱이다. 휴대폰에서도 등록·실행·계산이 가능해야 한다. Windows의 Chrome·Edge를 우선 검증하고 모바일 브라우저 한 종류에서 확인한다(가정). 별도 앱 설치는 없다.

개발 중에는 로컬 HTTP 서버로 실행하고, 실제 사용은 정적 웹호스팅으로 제공할 수 있다. 파일을 직접 더블클릭하는 file:// 실행은 지원 범위에서 제외한다. 설치형 앱과 완전 오프라인 보장은 후속 범위다. 외부 앱에는 해당 서비스의 인터넷 연결이 필요하다. 내부 계산 자체에는 서버 통신이 없다.

## 5. 사용자 흐름

첫 실행 → 기본 계산기와 등록 앱 목록 → 내부 앱은 같은 탭에서 실행 / 외부 앱은 새 탭에서 실행 → 허브에서 목록 관리 또는 백업. 내부 화면에는 항상 허브로 돌아가기 링크를 제공한다.

## 6. MVP 범위

필수: 프로그램 목록, 외부 링크 등록·수정·삭제, 내부 앱 등록 구조, 계산기, 브라우저 저장, JSON 백업·복원, PC 중심 반응형 화면, 키보드 접근.

후속: 검색·분류·즐겨찾기·순서 변경, 계산 기록, 설치형 웹앱, 기기 간 동기화. 첫 버전 제외: 계정·서버·DB·공동 편집·학생 기록·외부 AI 연동·앱 소스 업로드 및 실행.

## 7. 기능 요구사항

모든 FR의 사용자는 본인이고 우선순위는 필수다. 화면과 인수 조건은 아래 ID로 연결한다.

| ID | 기능·목적 | 입력·처리·출력 | 예외·완료 기준 | 화면 |
|---|---|---|---|---|
| FR-001 | 허브 목록·실행 | 코드의 내부 앱 목록과 저장된 외부 앱 목록을 합쳐 이름·설명·유형·실행 버튼 표시 | 초기에는 계산기 제공. 외부 앱 0개이면 등록 안내. 누락 경로는 오류와 복귀 링크 | S01 |
| FR-002 | 외부 앱 등록 | 이름·설명·주소 검증 후 고유 ID와 함께 저장 | 이름 1~60자, 설명 0~200자, 주소 최대 2048자(길이 제한은 가정). 앞뒤 공백 제거. http/https만 허용 | S02 |
| FR-003 | 외부 앱 수정·삭제 | 기존 필드 수정 또는 대상 이름을 표시한 삭제 확인 | 취소하면 변화 없음. 저장 실패 시 성공 안내 금지. 내부 앱 수정·삭제는 코드에서만 수행 | S02 |
| FR-004 | 로컬 저장·복구 | 버전이 있는 단일 목록을 localStorage에 저장, 시작할 때 검증 후 읽기 | 저장 차단·용량 초과·손상 시 안내. 손상 원문을 자동 덮어쓰지 않음. 사용자가 원문 다운로드 후 명시적으로 초기화 가능 | S01,S02 |
| FR-005 | 목록 백업 | 현재 외부 앱 목록을 버전·내보낸 시각과 함께 JSON 다운로드 | 빈 외부 목록도 유효. 내부 앱 코드·계산 기록·비밀값 제외. 다운로드 요청 발생까지 확인 | S03 |
| FR-006 | 백업 복원 | 파일 전체 검증 → 외부 앱 수·교체 범위 미리보기 → 확인 → 저장 성공 후 화면 반영 | 첫 버전은 외부 목록 전체 교체 방식(가정), 병합 없음. 취소·검증 오류·저장 실패 시 기존 상태 유지. 내부 앱은 영향 없음 | S03 |
| FR-007 | 기본 계산기 | 숫자, 소수점, + − × ÷, =, ±, AC, 한 자리 지우기 | 아래 계산 규칙과 AC-007~009 충족 | S04 |
| FR-008 | 내부 앱 확장 | 개발자가 고유 ID·이름·설명·내부 경로와 모듈을 코드에 추가 | 공통 디자인·복귀 링크·정리 함수를 준수. 추가 앱이 계산기·외부 목록을 깨지 않음 | S01,S04 |

계산 규칙(세부 동작은 가정): 일반 탁상 계산기처럼 입력 순서대로 계산한다. `2 + 3 × 4 =`는 20이다. 연산자를 연속 입력하면 마지막 연산자로 교체한다. 숫자당 소수점은 한 번만 허용하며, 소수점으로 시작하면 `0.`으로 처리한다. 결과 뒤 숫자 입력은 새 계산, 연산자 입력은 이어 계산이다. 반복 `=`는 결과를 유지한다. ±는 현재 입력 또는 결과의 부호를 바꾼다. 한 자리 지우기는 현재 숫자 입력만 편집하며 마지막 자리를 지우면 0이 된다.

입력은 부호·소수점을 제외한 숫자 12자리로 제한한다. 결과는 유효숫자 12자리 수준으로 정규화하고 필요하면 지수 표기한다. `0.1 + 0.2`는 `0.3`으로 보이게 한다. 음수 0은 0으로 표시한다. 비유한 결과·0으로 나눔은 사용자용 오류로 표시한다. 오류 뒤 AC 또는 새 숫자 입력으로 복구한다. 금융·성적 산정용 정밀 계산 도구는 아니다.

키보드: 0~9, 소수점, +, -, *, /, Enter 또는 =, Backspace, Escape를 지원한다. ±는 화면 버튼으로 제공한다. 입력창 편집 중 계산기 단축키를 가로채지 않으며 계산기 화면에서만 리스너를 활성화하고 이탈 시 해제한다.

## 10. 데이터 요구사항

사용자가 외부 앱 이름·설명·주소를 생성·수정·삭제한다. 해당 브라우저에서 사용자가 삭제하거나 사이트 데이터를 지울 때까지 보관한다. 계산값·계산 기록·학생 이름·성적·출결·계정·분석 로그는 저장하지 않는다. 목록에 민감정보나 토큰이 담긴 URL을 입력하지 않는다는 가정이다. 내려받은 백업은 사용자가 별도로 보관·삭제한다.

## 11. 데이터 모델

DB는 없다. localStorage 키 `teacher-hub.apps.v1` 아래 단일 JSON을 저장한다.

```json
{
  "schemaVersion": 1,
  "externalApps": [
    {
      "id": "외부-고유-ID",
      "name": "참고 도구",
      "description": "개인용 웹 도구",
      "url": "https://example.com/"
    }
  ]
}
```

id는 비어 있지 않은 고유 문자열, 나머지 필드는 FR-002 길이·형식 제한을 적용한다. name·url은 필수, description은 빈 문자열을 허용한다. 중복 이름·주소는 허용하되 ID 중복은 거부한다. 항목 삭제 시 해당 객체만 제거한다. 관계나 민감정보 필드는 없다.

백업은 위 구조에 `exportedAt` ISO 날짜 문자열을 추가한다. 파일명 예: `teacher-hub-backup-2026-10-17.json`. 스키마 버전·필드 자료형·필수값·URL·고유 ID를 전부 검증한다. 허용 필드만 새 객체에 복사하며 알 수 없는 필드는 적용하지 않는다. 지원하지 않는 버전은 거부한다. 파일 크기 1MiB, 항목 1000개를 상한으로 둔다(가정).

내부 앱은 `id/name/description/route/mount`를 가진 코드 레지스트리로 관리한다. 내부·외부 ID에는 각각 `builtin:`/`external:` 접두사를 사용해 충돌을 피한다. 내부 앱 소스는 백업 JSON에 포함하지 않는다.

## 12. 시스템 구성

브라우저 UI → 입력 검증 → 저장 모듈 → localStorage. 내보내기는 JSON 파일 다운로드, 가져오기는 사용자가 선택한 파일을 브라우저에서 읽는다. 내부 앱은 레지스트리에서 찾아 실행한다. 외부 앱은 검증한 URL을 새 탭에 연다.

프론트엔드만으로 충분하다. 백엔드·DB·인증·업로드 저장소가 필요한 중앙 공유나 계정 기능이 없기 때문이다. 새 내부 앱의 데이터 저장이 필요해지면 별도 요구사항과 저장 공간을 추가한다.

## 13. API와 외부 서비스

API 호출·외부 AI·비밀키는 없다. 외부 링크를 여는 것은 해당 사이트로 이동하는 동작이다. 허브는 외부 앱의 로그인·저장·가동 상태를 보장하지 않는다. 자동 미리보기·사이트 메타데이터 수집·iframe 삽입은 제외한다.

## 14. 로그인과 권한

회원가입·로그인·로그아웃·비밀번호·세션·계정 삭제는 해당 없음. 개인용 로컬 목록이므로 도입하지 않는다. 공개 호스팅하더라도 목록이 서버에 공유되는 구조가 아니다. 주소를 안다는 사실이 접근 제어를 제공하지는 않는다.

## 16. 개인정보·보안·접근성

수집하는 것은 사용자가 작성한 프로그램 메타데이터뿐이다. 브라우저와 수동 백업에 남으며 외부 AI로 전송하지 않는다. 본인 외 접근 제어는 없다는 점은 공유 PC 사용 전에 확인한다. 첫 버전은 학생 개인정보를 취급하지 않는 가정으로 진행한다.

개발 전: 본인이 사용하는 브라우저 프로필과 정적 사이트 접근 가능 여부 확인. 개인정보 기능을 추가할 경우 학교 담당자와 기관 정책을 별도로 확인한다.

개발 중: 텍스트를 HTML로 해석하지 않고 DOM 텍스트로 출력한다. URL은 URL 파서로 검사하고 http/https 외의 javascript/data/file 등을 거부한다. 새 탭에는 noopener/noreferrer를 적용한다. eval·문자열 함수 실행 없이 계산기를 구현한다. 백업은 데이터로만 읽고 실행하지 않는다. 복원과 삭제는 명시적으로 확인한다. 비밀값을 코드·백업·URL에 넣지 않는다.

배포 전: XSS 형태의 이름, 위험한 URL, 잘못된 백업, 저장 실패, 키보드와 대비를 검증한다. 보안 검토는 요구사항 수준이며 기관 승인·법률 검토·전문 보안 감사를 대신하지 않는다. 향후 학생 기록은 검토 전 실데이터로 구현하지 않는다.

## 17. 구현 기술 기준안

가정으로 HTML·CSS·JavaScript ES 모듈과 해시 기반 경로를 사용한다. 별도 프레임워크·UI 라이브러리·빌드 과정 없이 작은 첫 버전을 구성하기 위한 선택이다. 앱별 모듈과 공통 저장 모듈을 나눠 확장한다. 서버·DB·인증은 없다.

앱 화면의 상태가 복잡해질 경우 컴포넌트 프레임워크 전환을 후속으로 검토한다. 첫 버전의 설치·구성 난이도는 낮음, 직접 DOM 상태 관리와 모듈 정리는 중간 수준으로 본다. 정확한 도구 버전·가격·호스팅 업체는 이 문서에서 확정하지 않는다.

제안 구조:

```text
index.html
styles/tokens.css
styles/app.css
src/main.js
src/router.js
src/registry.js
src/storage.js
src/backup.js
src/validation.js
src/screens/hub.js
src/screens/app-form.js
src/screens/backup.js
src/apps/calculator/index.js
src/apps/calculator/engine.js
README.md
```

내부 앱의 mount(container)는 화면을 그리고 cleanup 함수를 반환한다. 라우터는 이동 전에 cleanup을 실행한다. `#/`는 허브, `#/apps/calculator`는 계산기다. 등록·수정·백업 화면도 명확한 해시 경로를 가진다. 내부 앱 경로는 허용된 코드 레지스트리에서만 찾는다.

## 18. 배포·운영

개발·검증은 로컬 HTTP 서버에서 수행한다. 운영은 정적 호스팅을 계획할 수 있으나 실제 배포와 계정 생성은 이번 명세 작성 범위가 아니다. 도메인·앱스토어·서버 환경변수는 필수가 아니다. 코드 업데이트는 선생님이 바이브 코딩 도구를 통해 수행한다.

같은 주소·프로토콜·포트·브라우저 프로필을 유지하면 같은 저장 공간을 사용한다. 운영 주소나 개발 포트가 바뀌면 다른 저장 공간으로 취급될 수 있으므로 변경 전에 백업한다. 웹앱 배포는 목록의 중앙 백업이 아니다. 정적 파일·개발 도구·선택적 호스팅·도메인이 비용 검토 항목이며 금액은 미확정이다.

## 19. 테스트 계획

계산 엔진은 순수 함수로 분리하여 사칙연산·소수점·부호·연산자 교체·반복 =·자리수 제한·비유한 결과를 검증한다. 저장·복원은 정상 왕복, 빈 목록, 취소, 손상 JSON, 지원하지 않는 버전, 중복 ID, 잘못된 URL, 크기 초과, 저장 예외를 검증한다.

화면에서는 등록→수정→삭제→새로고침, 내보내기→빈 브라우저에 가져오기, 계산기→허브→계산기 흐름을 확인한다. 저장값 손상 시 원문 보존과 복구 안내를 확인한다. PC·모바일 너비, 200% 확대, 키보드 이동, 화면 읽기 안내, 대비를 확인한다. 학생 실데이터는 쓰지 않는다.

## 22. 위험과 대응

브라우저 데이터 삭제 → 수동 백업과 복원 안내. 주소 변경 → 변경 전 내보내기. 외부 서비스 종료 → 해당 앱 수정·삭제. 계산 정밀도 → 출력 정규화와 범위 명시. 앱 확장 중 이벤트 중복 → cleanup 규칙. 얇은 글자·연한 색 → 가독성 조정·대비 검증. 공유 PC 노출 → 개인 브라우저 프로필 사용과 민감정보 제외. 잘못된 복원 → 전체 검증·미리보기·명시 확인·실패 시 원본 유지.

## 23. 확정·가정·미결정

확정: 개인용, 두 가지 앱 추가 방식, 계산기, 현재 브라우저 저장, 파일 백업, PC 우선·모바일 대응, 첨부 디자인, 로그인·서버·DB 없음.

가정: 가칭 교사 도구함, 일반 계산기 기능·입력 순서 연산, 계산 기록 미저장, 개인정보 없음, 외부 앱만 화면에서 관리, 복원은 전체 교체, 프레임워크 없는 모듈 구조, 길이·크기 제한, 모바일 너비와 테스트 환경, 한글 가독성을 위한 글꼴 굵기 조정. 구현 중 변경이 필요하면 이유를 기록한다.

미결정: 실제 호스팅·도메인·학교 네트워크 접근 가능 여부. 로컬 시제품 구현을 막지 않으며 배포 전에 확인한다. 학생 정보·기기 동기화가 필요해지면 범위를 재설계한다.

## 24. 쉬운 요약

선생님만의 프로그램 서랍을 만든다. 첫 칸에는 계산기가 있고, 다른 웹사이트 주소를 등록하거나 AI에게 새 도구 제작을 요청해 늘릴 수 있다. 목록은 현재 브라우저에만 저장된다. 다른 PC로 옮길 때는 백업 파일을 내려받아 가져온다. 백업은 프로그램 코드 자체를 복사하지 않는다.

## 25. 선택 이유

웹앱은 PC와 휴대폰에서 같은 화면 체계를 사용할 수 있다. 로컬 저장과 파일 백업이면 개인 목록 관리에 충분하다. 서버·계정·DB 운영을 추가할 필요가 없다. 작은 ES 모듈 구조로 시작하고, 앱별 파일·레지스트리로 확장한다. 단일 HTML 파일은 더 단순하지만 앱이 늘 때 수정 범위가 커지므로 채택하지 않는다. 디자인은 별도 UI 라이브러리 없이 CSS 토큰으로 적용한다.
